---
name: grilling
description: 就某个计划、决策或想法，不依不饶地盘问用户（grill）。当用户想对自己的思考做压力测试，或使用任何 "grill" 类触发短语时使用。
---

不依不饶地面谈用户，直到你们达成共识。把它画成一棵**设计树**：每个决策都会分叉出挂在其下的决策。

按**轮次**推进这棵树。**前沿（frontier）**指的是那些前提条件已经确定的所有决策：也就是你**现在**就能提问、不必去猜尚未听到的答案的那些问题。在一轮里把整条前沿都问出来：给每个问题编号，并给出你推荐的答案。然后等用户回答，再开始下一轮。

一轮的格式如下：

```
❓ **Q1** - **<问题标题>**：<问题正文，可以是多段，可包含多个选项>

➡️ <你推荐的答案>

---

❓ **Q2** - **<问题标题>**：<问题正文，可以是多段，可包含多个选项>

➡️ <你推荐的答案>
```

把每个问题都措辞成：回答 "是" 就等于接受你推荐的答案。

每一轮中用户的回答都会重塑这棵树：已确定的决策把前沿向外推，并解锁那些依赖它们的问题。重新计算前沿，再问下一轮。如果某个问题的答案依赖于本轮仍未解决的另一个问题，那它属于**之后的**轮次，而不是这一轮。

查找**事实**是你的工作，永远不是用户的工作。当某个前沿问题需要来自环境的事实（文件系统、工具等）时，派一个拥有全新上下文窗口的子 agent 去查；凡是你能自己查到的，就不要问用户。但不要因此阻塞：正在进行的探索是一个未确定的前提，所以只有它下游的问题才需要等子 agent 汇报；前沿中其余的问题现在就问。**决策**属于用户：把它们逐个交给用户，然后等待。

当整条前沿清空时，这次会话就结束了：设计树的每个分支都访问过，没有任何东西被默默假设。在用户确认你们已达成共识之前，不要开始动手。
