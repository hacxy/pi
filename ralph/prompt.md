# PRD

将本次调用附带的两份文档（PRD 与 PLAN）拉入你的上下文。

你会收到一个包含最近 10 条 Ralph 提交的文件（SHA、日期、完整消息）。审查这些提交，了解已完成的工作。

# 任务拆解

将 PRD 拆解为任务。

每个任务必须是最小的工作单元。我们不想超出自己的视野。目标：每个任务只做一个小改动。

# 任务选择

挑选下一个任务。

如果没有更多任务，输出 <promise>NO MORE TASKS</promise>。

# 探索

探索仓库，把完成该任务所需的相关信息填满你的上下文窗口。

# 执行

完成任务。

如果任何因素阻碍你完成任务，输出 <promise>ABORT</promise>。

# 反馈循环

提交之前，运行反馈循环：

- `npm run test` 运行测试
- `npm run typecheck` 运行类型检查

# 提交

进行一次 git 提交。提交信息必须：

1. 以 Conventional Commits 格式开头（如 `feat:`、`fix:`、`chore:`、`docs:`），并在末尾添加 `Ralph: <任务编号>` footer
2. 包含已完成的任务 + PRD 引用
3. 记录关键决策
4. 列出改动的文件
5. 记录阻塞项或下一轮迭代的注意事项

保持简洁。

# 最终规则

一次只做一个任务。
